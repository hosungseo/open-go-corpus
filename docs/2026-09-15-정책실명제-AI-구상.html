정책실명제, 실명은 이미 문서에 있다

기준일 2026-09-15
출처 open.go.kr 정책실명제 전수(중앙 2018~2026) · 원문공개 코퍼스 53.8만 건
작성 행정안전부 혁신기획과 (초안, 내부 검토용)

포털의 정책실명제 코너는 참여가 매년 줄고, 읽는 사람이 없으며, 지자체 데이터는 아예 없다. 반면 같은 포털의 원문공개에는 결재선 실명(기안·검토·협조·전결)이 붙은 결재문서가 하루 4천 건씩 쌓인다. AI가 할 일은 새 입력창을 만드는 것이 아니라, 이미 공개된 문서에서 실명과 경위를 끌어와 정책실명제를 자동으로 채우는 것이다.

1 · 현재 상태

포털에서 직접 긁어 확인한 수치다. 중앙행정기관 정책실명제 목록은 2018~2026년 전 연도·전 기관을 받았고(6,847건), 지자체 링크 261개는 하나씩 열어봤다.

A참여가 줄고, 등록은 늦어진다

B읽는 사람이 없다

사업당 조회수 중앙값은 2018년 10회에서 2024년 2회, 2025년 1회, 2026년 0회로 떨어졌다. 2025년 등록분의 38%, 2026년 등록분의 68%가 한 번도 열리지 않았다. 9년 누적 최다 조회 사업도 331회(경찰청 유치장 환경개선)에 그친다. 공개는 되고 있지만 도달하지 않는다.

C지자체·교육청은 포털에 없다

포털은 243개 지자체와 18개 교육청을 각 기관 홈페이지 링크로만 안내한다. 261개 링크를 전부 열어보니 3개는 404·응답없음(성남시·서천군·철원군), 14개는 메인 화면·업무추진비·로그인 화면 등 엉뚱한 곳에 떨어졌다(충남·제주시·서귀포시·대구교육청 등). 살아 있는 링크도 서식이 제각각이라 한 화면에서 비교하거나 검색할 방법이 없다.

D데이터가 코드가 아니라 글자다

선정기준은 규정상 6개 호인데 실제 값은 "대규모 예산 / 대규모예산 / 대규모 예산사업 / 예산사업" 식으로 15가지 이상 표기가 섞여 있고 473건은 비어 있다. 사업기간은 "계속 / 계 속 / 단년도 계속"이 따로 집계된다. 담당자란은 "○○○ 과장", "4급 ○○○", "○○○ 과장(줄바꿈)○○○ 사무관"처럼 성명·직급 순서와 인원 수가 기관마다 다르다. 6,847건 중 3,819건(56%)에 HTML 엔티티(&#40;)가, 1,583건(23%)에 깨진 물음표(가운뎃점 유실)가 그대로 노출된다.

E같은 사업이 매년 남남이다

기관+사업명이 같은 사업 1,380개가 두 해 이상 등록됐고 200개는 5년 이상 이어진다(관세청 '해외통관애로 해소', 지식재산처 '특허심사지원' 9년 연속). 그런데 해마다 새 ID로 올라가 연도 간 연결이 없다. 9년 치 담당자 변천이나 누적 추진실적을 이어 볼 수 없다는 뜻이다.

F상류(결재문서)는 이미 원문공개에 있다

원문공개 코퍼스 53.8만 건에서 제목에 '정책실명제'가 들어간 결재문서 260건(131개 기관)이 나온다. 심의위원회 개최계획·결과보고 143건, 운영계획 62건, 대상사업 선정 13건. 2026년분만 104건이고 대부분 지자체·교육청이다. 즉 포털이 담지 못한 지자체 대상사업 목록이 결재문서 첨부(HWP) 형태로 같은 포털 안에 공개돼 있다. 사업 상세의 '관련 원문' 칸도 마찬가지다. 연결된 사업은 35%뿐이고 그마저 기관별로 갈린다(기상청은 25건 중 22건 연결, 병무청·농림축산식품부·국세청·국방부 등 10개 기관은 0건). 그러나 연결된 원문에는 기안 > 검토 > 병렬협조 > 전결 결재선 실명이 통째로 들어 있다. 정책실명제가 요구하는 "관련자의 소속·직급·성명"이 바로 그것이다.

2 · 규정이 요구하는 것

행정업무의 운영 및 혁신에 관한 규정(대통령령, 2026-05-19 시행) 제63조~제63조의5. 포털의 데이터 모델과 나란히 놓으면 빈칸이 보인다.

규정요구 사항포털 현재
제63조 ①1 정책의 실명 관리결정·집행 과정에 참여한 관련자의 소속·직급·성명과 그 의견을 종합 기록담당자 1명(자유입력) + 추진실적별 결재선 2~3명. 의견은 없음
제63조 ①2관련 계획서·보고서·회의자료와 토의내용을 종합 기록'관련 원문' 칸 존재, 연결률 35%
제63조 ③보도자료에 담당부서·담당자·연락처 표기포털과 무관, 대조 불가
제63조의3 ①5 중점관리 대상 선정행안부장관이 정한 절차로 국민이 신청한 사업포털에 신청 창구 없음. 선정기준 '국민신청' 114건은 기관이 자체 접수
제63조의3 ③추진실적을 기관 홈페이지 등으로 공개중앙은 포털 입력, 지자체는 각자 홈페이지(링크 261개)
제63조의4 평가행안부장관이 추진실적 등을 평가할 수 있음평가에 쓸 정형 데이터가 없음(선정기준·기간 미코드화)
3 · AI로 할 수 있는 것

다섯 과제. 앞의 둘은 이번에 실제 데이터로 가능성을 확인했고, 뒤의 셋은 그 위에 얹는다. 자동화는 후보와 초안까지, 확정은 담당자가 한다.

가

사업 ↔ 결재문서 자동 연결 검증됨1순위

무엇을
정책실명제 사업마다 원문공개 결재문서를 자동으로 찾아 '관련 원문'을 채우고, 결재선에서 관련자 소속·직급·성명을 추출해 사업의 실명 명부를 만든다.
확인한 것
사업명에서 뽑은 키워드 2개로 포털을 검색하면 22개 사업 중 4개만 맞았다("주민자치회"→행안부 문서 2건, "홈택스"→국세청 2건). 사업명과 문서 제목의 어휘가 달라 단순 검색으로는 안 되고 의미 매칭(임베딩 + 기관·기간 필터 + LLM 판정)이 필요하다. 반대로 연결이 있는 사업은 문서당 결재선이 완전하다.
방법
사업 개요·추진내용 문장을 임베딩 → 같은 기관·같은 연도 결재문서 제목·요약과 대조 → 상위 후보를 LLM이 "이 문서가 이 사업의 결정·집행 문서인가"로 판정 → 담당자 확정. 결재선은 원문 메타에 이미 구조화돼 있어 추가 추출이 필요 없다.
난이도
낮음. 데이터가 모두 같은 포털 안에 있다. 하루 4천 건 신규 문서를 매일 대조하면 추진실적이 자동 갱신된다.
나

지자체 대상사업, 링크 대신 문서에서 수확 검증됨

무엇을
지자체·교육청의 '정책실명제 심의위원회 결과보고' 결재문서 첨부(HWP)에서 대상사업 표를 읽어 포털에 지자체 데이터를 처음으로 적재한다. 외부 링크 261개를 관리하는 대신 문서를 읽는다.
확인한 것
코퍼스에 정책실명제 결재문서 260건(2026년 104건), 첨부 보유율 98%. HWP는 rhwp로 표를 셀 단위 구조로 뽑을 수 있음을 이미 산업단지 문서 4,247개 표에서 확인했다. 지자체 심의 결과보고서는 "사업명·부서·담당자·선정사유" 표가 정형에 가깝다.
방법
원문공개 일별 수집에서 제목 '정책실명제' 문서를 걸러 → 첨부 HWP 표 추출 → LLM이 열 이름을 표준 스키마(사업명·부서·담당자·선정기준·기간)로 정렬 → 지자체별 목록 생성. 링크가 죽은 17개 기관부터 시작하면 효과가 바로 보인다.
난이도
중간. 서식이 기관마다 달라 LLM 정렬이 필요하나, 표 하나에 사업 수십 건이라 처리량은 작다.
다

9년 치 데이터 정제와 사업 계보 복원

무엇을
선정기준을 규정 6호 체계로 코드화, 기간 정규화, HTML 엔티티·깨진 물음표 복구, 담당자 문자열을 "성명·직급" 구조로 분리. 그리고 기관+사업명+개요 유사도로 연도 간 동일 사업을 잇는다(1,380개).
확인한 것
전 연도 6,847건을 이미 정형 JSON으로 확보했다. 오류 유형은 위 D항의 네 가지로 좁혀진다.
방법
규칙(엔티티·기간)은 스크립트, 분류(선정기준·사업 동일성)는 LLM. 결과는 정정 제안 목록으로 기관에 돌려주고, 포털 입력 화면에는 선택형 코드를 넣어 재발을 막는다.
난이도
낮음. 하루 작업이다. 다만 계보 복원의 판정 기준(명칭 변경 vs 별개 사업)은 사람이 정해야 한다.
라

추진실적·타임라인 자동 초안으로 입력 부담을 없앤다

무엇을
'가'에서 연결된 결재문서의 생산일시(PRDCTN_DT, 초 단위)로 사업 연혁을 자동으로 세우고, 문서 본문의 '추진경위·향후계획' 절에서 추진실적 문장 초안을 만든다. 담당자는 고치고 승인만 한다.
확인한 것
본문 417건 분석에서 41%가 문서 하나에 날짜 3개 이상의 절차 연혁을 담고 있었고, 추진경위 절은 "□·○" 헤더로 규칙적으로 뽑힌다. 현재 포털의 추진실적 항목은 중앙값 3건, 문장 길이 중앙값 36자로 사실상 한 줄이다.
방법
문서 → 본문 추출(rhwp) → 날짜·경위 절 추출 → LLM 요약 → 담당자 검토 화면. 참여율 하락의 원인이 입력 부담이라면 여기서 반전된다.
난이도
중간. 본문 생성이 문서당 5~10초(ESB 파이프라인)라 전량은 무리이고 연결된 사업 위주로 선별한다.
마

국민 쪽 창구: 질의응답과 국민신청

무엇을
"○○ 사업은 누가 언제 결정했나"를 자연어로 묻고 사업·문서·결재선으로 답하는 검색, 그리고 규정 제63조의3 ①5호가 예정한 국민신청 창구. 보도자료의 담당자 표기(제63조 ③)를 사업 담당자와 자동 대조하는 점검도 여기에 붙는다.
확인한 것
조회수가 0으로 수렴한 이유는 찾을 수 없어서다. 포털 검색은 제목 단어 AND 검색이라 사업명을 모르면 닿지 않는다. 신청 창구는 사이트맵에 없다.
방법
'가·나·다'로 만든 정형 데이터를 인덱스로 쓰는 질의응답. 근거 문서를 항상 같이 보여주고, 없는 것은 없다고 답한다.
난이도
데이터가 갖춰진 뒤의 일이다. 앞 과제 없이 챗봇만 얹으면 빈 데이터를 유창하게 말하게 된다.

운영 관제도 같은 데이터로 바로 만들 수 있다: 미등록 기관 알림(2025년 등록 30개 중 2026년 미등록 23개), 등록 마감 추이, 죽은 링크 점검, 조회 0 사업 비율. 실장 보고용 한 화면이면 충분하다.

4 · 진행 순서

포털 개편 없이 시작할 수 있다. 수집기·본문 추출기·HWP 표 파서는 이미 있고, 이번 진단도 그 도구로 반나절에 끝냈다.

2주 · 스파이크

행안부 자체 사업으로 증명

  • 2025년 행안부 54건에 '가' 자동 연결 적용, 담당자 검수로 정밀도 측정
  • '다' 정제 결과를 전 부처 정정 제안 목록으로 산출
  • 죽은 링크 17개 기관에 '나' 적용해 지자체 첫 데이터 적재
3개월 · 파일럿

부처 3곳 + 시도 2곳

  • 연결·초안('가·라')을 담당자 화면으로 제공, 입력 시간 전후 비교
  • 지자체 심의 결과보고 → 포털 적재 파이프라인 일 단위 운영
  • 정밀도·오탐 기준을 운영지침 초안으로 문서화
그 후 · 포털 반영

입력 화면과 국민 창구

  • 선정기준·기간 선택형 코드, 연도 간 사업 ID 계승
  • '관련 원문' 자동 제안을 포털 기본 기능으로
  • 질의응답·국민신청('마') 공개
5 · 근거와 한계

수치는 2026-09-15 포털 상태의 스냅샷이다.

  • 정책실명제 목록: 포털 polRnInsttList.ajax(기관 목록)과 polRnBList.do(기관별 사업, 페이지에 JSON 내장)에서 2018~2026년 중앙행정기관 6,847건 전수. 세션 없이 받아진다. 사업 상세(polRnInsttDetail.do)는 2025~26년 784건을 열어 추진실적·결재선·관련 원문을 확인했다. 관련 원문이 있는 사업은 문서 수 중앙값 13건.
  • 지자체 링크: 정책실명제 첫 화면의 외부 링크 261개를 HTTP로 열어 상태코드·최종 URL·페이지에 '실명' 문자열 포함 여부를 봤다. '엉뚱한 곳' 판정은 그 문자열 부재 기준이라 실제로는 더 많을 수 있다.
  • 원문공개 코퍼스: 2026-08-22 수집분(원본 138만 행, 큐레이션 53.8만 건, 본문 417건). '정책실명제' 제목 문서 260건은 큐레이션 코퍼스 기준이라 전체 포털에는 더 많다.
  • 원문공개율: 포털 통계 기준 중앙행정기관 55곳 등록 90,224건 중 공개 37,985건(42%, 2026-08-31 기준). 대검찰청 1%, 국방부 10%, 경찰청 13%. '가'의 연결 가능 범위는 이 공개율에 갇힌다.
  • 조회수는 포털이 상세 페이지 진입 시 올리는 값이라 봇·내부 확인이 섞일 수 있다. 낮은 쪽으로 편향되지는 않으므로 "읽히지 않는다"는 판단에는 보수적이다.
  • 2026년 수치는 등록이 진행 중인 값이다. 다만 2025년 등록 30개 기관 중 23곳이 9월 중순까지 미등록이라는 사실 자체는 확정이다.
  • 담당자·결재선 실명 데이터는 개인정보를 포함한다. 수집분은 로컬에만 두었고, 이 문서에는 개인 이름을 싣지 않았다.
