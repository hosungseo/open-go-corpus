# 표시 숫자 정비 — 전수 목록과 결정 (2026-09-16)

기준: HEAD 90657fa (개요 CryptoCalc 교체분). 대상은 `docs/src/index.html`·`compare.html`·`policy2.html`·`explorer/template.html`의 본문 표시 숫자. 조문 번호(§7·§63 등)와 문서번호는 데이터가 아니라 제외.

결정 기준 세 가지:
- **유지** — 판정 문장을 직접 받친다.
- **빼기** — 판정과 무관한 세부거나, 독자가 해석할 수 없거나, 같은 사실을 다른 숫자가 이미 말한다.
- **고치기 / 확인** — 페이지 간 불일치, 합계 불일치, 출처 미상.

결정 요약: 글자수 계열 전부 빼기(사용자 결정). 분포 나열·꼬리값·파생값·중복 빼기. 개요와 정책실명제 2.0의 헤더 통계 통일.

## 2. 빼는 이유 (묶음별)

### 글자수 계열 (26~35, 38의 33자, 90의 28,659자) — 사용자 결정
"정책실명제 개요는 짧고 원문은 길다"를 정량화한 것인데, 독자는 148자와 28,659자로 그걸 아는 게 아니라 1층의 "개요 한 문단 / 링크 너머 / 본문+첨부 원본"으로 이미 안다. 190배는 분량 비율일 뿐 "무엇이 빠져 있나"를 말하지 않는다. 백분위는 분석 노트이지 독자용이 아니다.

빼고 나면 2층 항목 05 "내용의 분량"이 빈다. 선택지:
- **정성으로 바꾸기 (권장)**: 판정 "내용은 원문에만 있다". 세 칸은 "사업개요 한 문단(예산·경과 없음) / 제목 한 줄, 본문은 기관 홈페이지 / 본문 + 첨부 원본, 결재란 포함". 숫자 0개.
- **항목 삭제**: 1층 "내용 본문이 포털 안에" 행은 남기되 2층 없음. 2층 14개.

### 분포 나열 (39, 42, 61 일부, 64 일부)
글로 쓴 히스토그램. 독자는 머릿속에 그리지 못하고, 중앙값(연 3건)·비율(35%)·판정에 필요한 값(분기 3, 국정과제 291·국민신청 5)이 이미 결론을 낸다. 정밀도만 올리고 결론은 안 바꾼다.

### 꼬리값·파생값 (28~30, 32, 35, 45, 49, 57, 69, 73)
백분위, 최댓값, 평균의 평균. 49(기관당 20.6건)는 "권고 30건"과 비교하려던 것인데 각주가 30건을 미확인으로 두어 비교가 성립하지 않는다.

### 합계 불일치 (51, 87)
51은 더하면 26.1만인데 총계 246,604. 87은 더하면 1,151인데 "1,170개". 더해 보는 독자가 페이지 전체를 의심한다. 51은 확인 전까지 빼고, 87은 "첨부의 절반이 HWP"로 바꾼다.

### 중복 (2, 5, 22, 56, 63, 72, 78, 79, 81)
같은 사실의 두 번째 이상 등장, 또는 한 논점을 두 숫자로 말하는 경우. 22(4,702)는 6,847과 나란히 서면 모수가 둘로 보인다. 56(31%)은 58(53건)이 더 직접 말한다. 72(누적 12.9회)는 누적 기간을 독자가 몰라 해석이 안 되고 74(84%)가 같은 말을 선명히 한다.

### 페이지 밖 정보 (12, 95, 117의 270KB)
쪽수·파일 크기·코퍼스 메타 행 수. 어느 판정에도 안 쓰인다. 95(53.8만)는 143만(원문 등록)과 혼동 위험만 있다.

### 의미가 약하지만 남기는 것
14·15(450곳·88곳), 23~25(9·6·38개 필드), 40(원문 41% 연혁), 44(링크 120 중 10 오류), 102(최종 갱신). 판정을 직접 받치진 않지만 셀 구조를 채우고 있어 빼면 빈칸이 된다.
