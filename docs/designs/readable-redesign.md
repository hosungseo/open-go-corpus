## Problem Statement
정보공개 3제도 페이지 4개(랜딩·비교분석·AI 구상안·대조기, hosungseo.github.io/open-go-corpus)를 실장(고위공무원단)이 "전반적으로 보기 힘들다"고 했다. 내용·수치는 맞지만, 웹 문서로서 한 화면에 요소가 너무 많고 글자가 작으며 결론이 근거 뒤에 있다. 독자는 실장과 국무회의 자료 작성자(사무관). 보고서(한글)를 쓰는 것이 아니라 **웹 문서 형식 그대로** 읽기 쉽게 만드는 것이 목표다.

## What Makes This Cool
사업 하나를 고르면 세 제도의 실물이 나란히 놓이는 대조기는 그대로 두고, 그 앞에 "요약 → 핵심 → 별첨"이라는 같은 읽기 문법을 네 페이지에 깐다. 실장은 어느 페이지를 열어도 첫 화면에서 결론 한 문장과 큰 숫자 셋을 보고, 원하면 아래로 내려가 근거를 본다.

## Constraints
- 형식은 웹 문서. 개조식 보고서로 바꾸지 않는다(사용자 명시).
- 선택지(폐지·유지·편입) 절은 페이지에서 뺀다. 판단은 실장 몫. 그 절에 딸린 각주·수치는 삭제하지 않고 별첨 근거에 남긴다.
- 접기(details)·호버 툴팁·클릭해야 보이는 범례 금지.
- 수치·각주·대조 데이터는 그대로. 바꾸는 것은 정보 구조·문체·타이포그래피.
- 단일 HTML + 인라인 JSON(대조기), 외부 라이브러리 없음. 배포는 기존 GitHub Pages(main/docs).
- 담당자·결재선 실명은 배포본에 없어야 한다(대조기 빌드 마스킹 유지). 정적 3페이지에는 실명이 없음을 2026-09-15 검사로 확인했고, 재작성 후 같은 grep 검사를 반복한다.
- 전문 용어(AJAX·gclfCd·JSON·ESB·임베딩) 본문 노출 금지. 대체어: 포털 조회, 사업 ID, 결재문서, 의미 기반 자동 연결.
- 기준 뷰포트 1366×768(브라우저 뷰포트 기준, 화면 해상도 아님). h1은 요약 블록 안에 두고, 상단 고정 바 40px + 요약 블록(h1 포함) 620px 이하로 첫 화면에 들어간다. 컨테이너는 `max-width` + `width:100%`(본문 960px, 3열·표 1180px)이며 861~1180px 폭에서도 페이지 가로 스크롤이 생기지 않는다(3열은 `minmax(0,1fr)`, 표만 내부 가로 스크롤). 860px 이하에서는 3열·카드가 세로 적층.
- 테마: 라이트 고정(`color-scheme: light`, 다크 토큰 제거). 인쇄: `@media print`에서 별첨 회색 바탕 제거, 상단 바는 `position: static`으로 첫 페이지 상단에 한 번 인쇄(기준일·범례 유지).
- 웹폰트는 Google Fonts(Noto Serif KR·IBM Plex Sans KR·IBM Plex Mono)에 시스템 폴백(Apple SD Gothic Neo, Malgun Gothic, system-ui). 정부망·오프라인에서 폴백 고딕으로 표시되는 것을 수용한다.

## Premises
1. 문제는 정보 부족이 아니라 웹 문서로서의 가독성(밀도·글자 크기·위계·화면당 메시지 수)이다. — 동의(사용자 정정: 보고서 형식 전환은 아님)
2. 그대로 두면 실장은 페이지를 안 보고 구두 설명에 의존하며 페이지는 근거 저장소로만 남는다. — 동의
3. 수치·각주·대조 데이터는 유지, 정보 구조·문체·타이포그래피만 바꾼다. — 동의
4. 배포는 기존 GitHub Pages 파이프라인으로 충분. — 동의
5. 선택지는 페이지에서 뺀다. — 동의

## Approaches Considered
### Approach A: 최소 손질 (CSS·순서·용어만)
빠르지만 화면당 요소 수가 그대로라 빽빽함이 남고 페이지 간 통일감 없음. Completeness 6/10. 기각.
### Approach B: 공통 문법 재구성 (요약 → 핵심 → 별첨)
네 페이지에 같은 규칙을 적용. Completeness 9/10. 채택.
### Approach C: 브리핑 단일 페이지
입구만 고쳐지고 상세 페이지는 그대로 힘듦. Completeness 7/10. 기각.

## Recommended Approach
B. 네 페이지에 아래 공통 문법과 토큰을 적용한다.

### 읽기 문법 (모든 페이지 공통)
- **상단 고정 바**(sticky, 40px): 페이지 이름 4개 링크 · 기준일 2026-09-15 · 제도 3색 범례. 860px 이하에서는 두 줄로 줄바꿈(높이 자동, 페이지 이름은 두 글자 약칭: 개요·비교·구상·대조). 어느 폭·어느 위치를 캡처해도 기준일·범례가 찍힌다.
- **요약 블록**(첫 화면, h1 포함 620px 이하): h1 + 결론 1~2문장 + 큰 숫자 **정확히 3개**(각각 한 줄 설명·출처 절 이름) + "근거·방법" 앵커(`#basis`) 링크 하나. 각주 위첨자 없음. `2018→2026`처럼 화살표로 잇는 연도 변화 값은 한 개로 센다. 랜딩은 별첨이 없으므로 `#basis`가 `explorer/#basis`로 간다.
- **핵심 절**(2~4개, 랜딩 제외): 절 제목이 결론 문장(h2). 절 도입부는 3문장 이내. 하위 항목은 목록 허용, 항목당 2줄 이내. 산문 문장 안의 숫자는 절당 3개 이내(표·카드 셀의 값은 제외). 본문 표는 4열 이하.
- **별첨 절**(`#appendix`, 회색 바탕, 라벨 "별첨"): 상세 비교표·기관 매트릭스·링크 상태·각주(`#basis`)·방법·한계. 밀도 규칙 예외(열 수 제한 없음, 가로 스크롤 허용). 접지 않는다.
- **각주 앵커**: 대조기의 `n_*` ID와 `data-note`·`data-v` 참조는 변경하지 않는다(빌드의 무결성 검사가 이 ID에 묶여 있음). 정적 페이지의 각주 번호·순서는 유지하고 위치만 별첨으로 옮긴다.
- **색 규칙**: 강조색 `--em`(진청)은 요약 결론 문장의 강조 구절 한 곳에만 쓴다. 링크는 `--ink` + 밑줄(강조색 아님). 제도 3색(적·황토·청록)은 열 제목 상단 선과 범례에만 쓰고 본문 강조에 쓰지 않는다.
- **기호**: ●◐○는 유니코드 대신 인라인 SVG 원(채움 100/50/0%)으로 그려 윈도우 폰트에서도 같게 보이게 한다.

### 페이지별 구조
- **랜딩**: 상단 바 → 요약 블록 → 페이지 3개 카드(각 한 줄 결론 + 링크) → 출처 한 줄. 핵심 절·별첨 규칙의 예외(카드가 핵심 절을 대신).
- **비교분석**: 요약 → ●◐○ 매트릭스(4열 표, 셀 값만 인라인 SVG 원; 860px 이하에서도 표 유지·내부 스크롤) → 물으신 것 6개(각 제목 1줄 + 답 3줄) → 같은 사업 3채널(사례 3건 × 3열 표: 국민비서·풍수해보험·주민자치회) → 별첨(상세 비교표 10행, 나머지 사례 3건, 근거·한계). 선택지 절 삭제, 딸린 각주는 별첨 유지.
- **AI 구상안**: 요약 → 현황 6가지(각 결론 헤드라인 + 2줄) → 과제 5개(표: 무엇·확인한 것·난이도, 각 1줄) → 로드맵(3열 카드) → 별첨(규정 대비표, 근거·한계).
- **대조기**: 상단 바 → 요약(결론 + 비율 스트립 3지표) → 예시 사업 3열(기본 '풍수해보험사업 운영' 2025, 해시 없을 때 자동 선택; 상수 하나로 교체) → "다른 사업 고르기"(필터·목록, 3열 아래; 목록 클릭 시 위 3열 교체 후 3열 상단으로 스크롤; 공유는 기존 `#p=<사업ID>|<연도>` 유지) → 물으신 것 6개 → 별첨(`#scoreboard` 스코어보드 상세 3열 카드(관련원문 연결 35%·사업당 조회 중앙값 포함), 기관 매트릭스 9년치, 지자체 링크 상태, 각주 `#basis`, 방법·한계). 해시 규칙: `#p=`로 시작하는 해시만 사업 선택 상태로 해석하고, `#basis`·`#scoreboard` 등 다른 해시는 앵커로만 처리하며 선택 상태는 유지한다(초기 진입이면 기본 사업 선택 후 앵커로 스크롤).
- 3열의 "첫 화면" 목표는 요약 블록에만 적용한다. 3열은 열 제목과 첫 항목이 첫 화면에 보이면 충분하며, 결재문서 목록은 5건으로 제한(이미 구현).

## Open Questions

## Success Criteria
- 1366×768에서 각 페이지 첫 화면에 결론 문장과 숫자 3개가 스크롤 없이 보인다(요약 블록 620px 이하). 스크린샷으로 검수.
- 어느 위치를 캡처해도 상단 고정 바(기준일·범례)가 찍힌다.
- 본문 최소 17px, 요약 블록 큰 숫자 정확히 3개, 강조색 한 화면에 1곳 이하.
- 대조기 빌드의 각주·값 무결성 검사와 실명 누출 검사 통과. 정적 3페이지는 실명 grep 검사 0건.
- 860px·1024px·1366px 폭에서 가로 스크롤이 페이지 본문에 생기지 않는다(표 컨테이너 안에서만). 세 폭 모두 스크린샷으로 검수.
