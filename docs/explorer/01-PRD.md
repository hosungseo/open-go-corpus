# PRD — 정보공개 3제도 대조기 (가칭)

작성 2026-09-15 · 상태 초안 · 근거 데이터 `FINDINGS.md` §11–§12

## 1. 서비스 한 줄 정의
정책실명제·사전정보공표·원문공개가 **같은 사업을 각각 무엇으로, 얼마나 깊이, 얼마나 자주** 공개하는지 실측 데이터로 나란히 보여주는 관측 페이지.

## 2. 타깃 사용자
| 순위 | 누가 | 무엇을 하려고 |
|---|---|---|
| 1차 | 참여혁신조직실장·국장·정보공개과 담당 | "제목만 공개되나?", "분기별 갱신되나?", "공공기관도 하나?" 같은 질문에 팩트로 답을 얻고 활성화·축소 판단의 근거를 확보 |
| 2차 | 국무회의 자료 작성자(혁신기획과) | 자료에 넣을 수치·표를 출처와 함께 가져가고, 회의 중 스크린샷 한 장으로 설명 |
| 후속 | 기자·연구자(공개 전환 시) | 제도 실태 인용 |

내부용이 먼저다. 담당자·결재선 **실명은 빌드 단계에서 제거**하고 역할·직급 구조만 남긴다.

## 3. 사용자가 겪는 핵심 문제
- 세 제도의 공개 범위·주기·이용을 **지침 문구로만 알고 실물을 본 사람이 없다.** 그래서 "사전공표에 포섭되면 정책실명제는 필요 없는 것 아닌가"라는 판단이 팩트 없이 오간다.
- 정책실명제 지자체 데이터는 포털 밖 261개 홈페이지에 흩어져 있고, 원문·사전정보는 검색 화면이 따로라 **같은 사업을 세 채널에서 동시에 볼 방법이 없다.**
- 포털 통계는 건수만 보여주고 깊이(항목당 글자 수·필드 유무)·갱신(등록 후 수정 여부)·이용(조회 0 비율)을 보여주지 않는다.

## 4. 이 서비스가 주는 핵심 가치
- **사업 이름 하나를 고르면 세 채널의 실물 레코드가 한 화면에** 나란히 놓인다. 깊이 차이가 설명 없이 보인다.
- 모든 숫자에 **스냅샷 날짜·표본 크기·산출 방법**이 붙어 회의 자료에 그대로 인용할 수 있다.
- 접힘·호버 없이 **스크린샷 한 장이 질문 하나에 답**한다.

## 5. 핵심 기능
1. **스코어보드** — 제도별 근거·대상·단위·깊이·주기·규모·이용 실측치 3열 카드
2. **사업 대조기** — 정책실명제 사업(중앙 2018–2026, 6,847건) 검색 → 선택 → 정책실명제 레코드 / 사전정보 검색 결과 / 원문 검색 결과 + 관련원문 결재선 구조를 3열로
3. **기관 현황** — 연도×기관 등록 매트릭스, 기관별 조회수 중앙값·원문 연결률, 지자체 링크 생존 상태
4. **근거 패널** — 각주·방법·한계 상시 노출, 각 수치에서 앵커로 이동

## 6. MVP에 필요한 기능
- 1·2·3·4 전부, 단 **정적 스냅샷 데이터로만**(빌드 시점 JSON). 사업 대조기의 사전정보·원문 히트는 사전 배치 수집분(2025–2026년 784건)만 제공하고 나머지 연도는 "대조 미수집" 표시
- URL 해시로 특정 사업·기관 화면 공유(`#p=<gclfCd>`, `#org=<nstCd>`)
- 데이터 재생성 명령 하나(`node tools/build-explorer.mjs`)

## 7. 지금은 제외할 기능
- 포털 실시간 검색(세션 필요, 429 제한) — 배치 수집으로 대체
- 로그인·편집·댓글, 정책 판단·권고(선택지 섹션), AI 질의응답
- 지자체·교육청 정책실명제 사업 데이터(포털에 없음, 2차 과제 '나'의 결과물이 생기면 추가)
- 공공기관 경영공시(ALIO) 항목 대조
- 실명 표시(내부 로컬 빌드 플래그로만 가능, 배포본에는 없음)

## 8. 성공했다고 판단할 기준
1. 실장이 페이지만 보고 회의에서 나온 질문 6개(공개 범위·사전공표 범위·주기·공공기관·국민신청·실태)에 스스로 답할 수 있다
2. 국무회의 자료에 들어가는 모든 수치가 페이지의 특정 앵커와 1:1로 대응한다
3. 사업 검색 → 3채널 대조 화면까지 10초 이내, 클릭 2회 이내
4. 어느 섹션이든 스크린샷 한 장에 범례·기준일이 함께 찍힌다
5. 수집 스크립트 재실행 → 빌드 한 번으로 스냅샷이 갱신되고, 기준일이 자동으로 바뀐다
